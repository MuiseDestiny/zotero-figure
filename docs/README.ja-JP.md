# Zotero Figure

Zotero の PDF から図表をローカルで抽出します。

[English](../README.md) | [简体中文](README.zh-CN.md) | [Italiano](README.it-IT.md) | [Русский](README.ru-RU.md) | [日本語](README.ja-JP.md) | [Español](README.es-ES.md)

Zotero Figure は PDF ページを端末上で描画し、DocLayout-YOLO で図、表、キャプションを検出して、抽出画像を PDF リーダーの専用サイドバーに表示します。PDF や推論データを外部サービスへ送信しません。

> 検出モデルは誤る場合があります。プラグインのクラッシュ、インストール問題、再現可能な連携不具合は報告してください。検出精度そのものは主にモデルに依存します。

## 機能

- 図と表をローカルで検出。
- 最適化 Q8 モデルを XPI に内蔵し、インストール済みコピーを正確なサイズと SHA-256 で検証。その検証済みバイト列を Worker に渡し、推論前に SHA-256 を再検証。
- 添付ファイルごとの結果索引を JSON、抽出画像を PNG として Zotero データディレクトリに保存。
- 再解析時にページ単位でローカル結果を置換するか、不足分だけを追加。
- 解析をキャンセル可能。推論中のキャンセルでは稼働中の Worker を終了し、後続処理のために再構築します。検出用描画は 640 px のままです。結果がある各ページは最大 4 倍、1,200 万画素、各辺 8192 px の範囲で一度だけ高解像度描画し、その 1 枚から検出されたすべての矩形を切り抜きます。
- 抽出可能なテキストがないページもスキップせず検出対象にします。テキストがあるページでは、英語、中国語、イタリア語、ロシア語の完全な図表表記を使って候補をより厳密に絞り込みます。
- PDF リーダー左側の Zotero Figure アイコンを唯一のメイン入口として使用。リーダー上部のツールバーにはボタンを追加しない。
- 幅に追従するカードと、**すべて**、**図**、**表**の順に並ぶフィルターで結果を閲覧。各フィルターには該当する結果件数も表示されます。ローカル PNG は表示領域の近くで遅延読み込みされ、取り消し可能な Blob URL と最大 3 件の同時画像読み込みを使用します。
- 長いキャプションは既定で折りたたまれ、クリックで展開または再度折りたためます。
- サイドバーのアクションバーから解析、キャンセル、全結果のノート追加、更新、ローカル結果の消去を実行。消去するとサイドバーは直ちに空になり、JSON と PNG はバックグラウンドで削除されます。既存の Zotero 注釈ミラーは削除されません。
- Zotero PDF Translate がインストールされていれば、アクションバーでキャプションを翻訳し、もう一度押して原文に戻せます。成功した翻訳は対象言語ごとにローカルキャッシュされ、再利用されます。
- 既存のローカル結果は、アクションバーから必要なときに Zotero 注釈のミラーへ変換できます。
- 各カードのメニューから画像のコピーまたは保存、該当ページへの移動、ノートへの追加、削除が可能。
- 必要に応じて、結果を `Figure N` または `Table N` タグとキャプションコメント付きの Zotero 標準画像注釈として複製。既定では無効。
- 1 枚または全結果から、PNG を実体のある埋め込み添付ファイルとして含む Zotero ノートを作成。注釈ミラーがなくても、ノート画像をクリックすると元 PDF の対応する切り抜き位置へ移動できます。
- 英語、簡体字中国語、イタリア語、ロシア語の UI。

## 必要環境

- Zotero 9 のみ。
- [最新リリース](https://github.com/MuiseDestiny/zotero-figure/releases/latest)の XPI。

現在のローカル推論では Java と `pdffigures2.jar` は不要です。

## インストールと設定

1. 最新リリースから `zotero-figure.xpi` をダウンロードします。
2. Zotero の `ツール > プラグイン` でファイルからのインストールを選び、XPI を指定します。
3. PDF を開き、左サイドバーの Zotero Figure アイコンを選んで解析を開始します。内蔵モデルは自動的に準備・検証され、別途ダウンロードは不要です。

## 内蔵モデル

Zotero Figure は最適化 Q8 `optimized-q8-d5d1e664` のみを内蔵します。サイズは 20,552,482 バイト、SHA-256 は `d5d1e664fbe639e716be7011aa7493b40f4ab498374b2157988c2ea41bf70daf` です。XPI から Zotero データディレクトリの `zotero-figure/models/` にコピーし、解析前に検証します。

XPI を入手した後は、モデルのために GitHub や Hugging Face へ接続する必要はありません。同一 XPI を GitHub Releases と地域ミラーで配布し、SHA-256 が一致することを確認してください。詳細は[配布ポリシー](MODEL_DISTRIBUTION.md)を参照してください。

## 使い方

1. Zotero リーダーで PDF 添付ファイルを開きます。
2. 左サイドバーの Zotero Figure アイコンを選択します。リーダー上部のツールバーに Zotero Figure ボタンはありません。
3. アクションバーの **図表を解析** を選び、ページ描画と検出の完了を待ちます。
4. **すべて**、**図**、**表**を切り替えます。カードメニューから画像のコピーまたは保存、該当ページへの移動、ノートへの追加、削除を実行できます。
5. Zotero PDF Translate がインストールされていれば、言語ボタンでキャプションを翻訳し、もう一度押して原文に戻します。
6. 必要に応じて **全結果をノートに追加**、**更新**、**ローカル結果を消去**を使用します。消去対象はプラグインのローカル JSON と PNG のみで、既存の Zotero 注釈ミラーには影響しません。
7. 同期される画像注釈も作成する場合は、プラグイン設定で **解析後に結果を Zotero 注釈へ同期**を有効にします。既定では無効です。

サイドバーは常にプラグイン独自のローカル結果ストアを読み込みます。PDF 添付ファイルごとのメタデータは Zotero データディレクトリ内の `zotero-figure/results/<libraryID>/<attachmentKey>/manifest.json` に、PNG は隣接する `images/` ディレクトリに保存されます。schema v3 の manifest は、対象言語別のキャプション翻訳と、バージョン付きの画像キャッシュ識別情報を保存します。添付元フィンガープリント（ファイルサイズと更新日時。取得できない場合は Zotero アイテムのバージョンにフォールバック）、解析バージョン、モデルハッシュ、プレビューバージョン、結果フィンガープリントが同じで PNG ファイルも存在する場合に限り、再解析ではその PNG を再利用します。manifest、翻訳キャッシュ、PNG は Zotero Sync の対象ではありません。注釈同期を有効にすると、同期や他プラグインとの互換性のために標準注釈のコピーが追加作成されますが、サイドバーのデータソースは変わりません。ノート内の画像は埋め込み添付ファイルであり、ローカル PNG パスへのリンクではありません。注釈ミラーを無効にしていても、ノート画像をクリックすると元 PDF の対応する切り抜き位置へ移動できます。

モデルと Worker の準備はリーダーのアイドル時に開始されます。準備完了前に解析を始めた場合、初回は時間がかかることがあります。処理時間は PDF、CPU、利用可能メモリによって変わります。

解析中に同時にスケジュールされるページは最大 3 件です。各ステージは個別に制限され、検出は最大 2 ページ、検出用ページ描画は 1 件、高解像度プレビューは 1 ページ、保存処理は 1 件まで並行します。検出ページは 640 px で描画します。キャッシュにない結果ページは最大 4 倍、1,200 万画素、各辺 8192 px の範囲で一度だけ PDF を描画し、すべての結果矩形をその同じ画像から切り抜きます。単一の推論 Worker を再利用し、Zotero 用の論理処理能力を残しながら最大 4 本の WASM スレッドを利用できます。実行中の推論をキャンセルすると Worker を終了し、CPU を消費し続けることを防ぎます。単一 Worker によりモデルセッションの重複も避けます。

## プライバシー

検出は Zotero 内の Transformers.js と ONNX Runtime Web で実行されます。PDF ページを外部サービスへ送信せず、実行時にモデルをダウンロードしません。

ローカルの結果 JSON と PNG は Zotero データディレクトリに残ります。ユーザーがそのディレクトリを別途バックアップまたは同期するか、注釈同期を有効にして追加コピーを作成しない限り、端末外へ送られません。

## 開発

Node.js 20.10 以降が必要です。

```bash
npm install
npm run check
npm run build
```

`npm run check` はフォーマット、ESLint、TypeScript、テスト、バンドルを検証します。`npm run build` は `build/zotero-figure.xpi` を生成します。`npm start` の前に `scripts/zotero-cmd-default.json` を `scripts/zotero-cmd.json` へコピーし、ローカルの Zotero パスを設定してください。

## アーキテクチャ

| パス                  | 責務                                          |
| --------------------- | --------------------------------------------- |
| `src/domain`          | Zotero に依存しないレイアウト型と照合ロジック |
| `src/features`        | リーダー UI と設定                            |
| `src/services`        | 解析、推論キュー、画像切り出し、ローカル保存  |
| `src/platform/zotero` | Zotero API との型付き境界                     |
| `addon`               | Bootstrap、翻訳、Worker、モデル情報           |
| `scripts`, `tests`    | 再現可能なビルドと自動検証                    |

ドメインロジックは Zotero のグローバル変数に依存させず、非公開 API へのアクセスはプラットフォームアダプターへ隔離します。

## 現在の制限

優先順位付き一覧は [docs/KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md) にあります。主な残課題はスキャン PDF からのキャプション抽出、Zotero リーダーの非公開 API リスク、実際の Zotero 9 環境でのエンドツーエンドテストです。
