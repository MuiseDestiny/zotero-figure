# Zotero Figure

Zotero の PDF から図、表、数式をローカルで抽出します。

[English](../README.md) | [简体中文](README.zh-CN.md) | [Italiano](README.it-IT.md) | [Русский](README.ru-RU.md) | [日本語](README.ja-JP.md) | [Español](README.es-ES.md)

Zotero Figure は MuPDF WASM で PDF 添付ファイルを端末上に直接読み込み、DocLayout-YOLO で図、表、独立数式、キャプション、表の脚注を検出して、抽出画像を PDF リーダーの専用サイドバーに表示します。解析に Reader を開く必要はなく、PDF を外部サービスへ送信しません。

> 検出モデルは誤る場合があります。プラグインのクラッシュ、インストール問題、再現可能な連携不具合は報告してください。検出精度そのものは主にモデルに依存します。

## 機能

- 図、表、独立数式をローカルで検出。
- 最も近い表脚注を表の切り抜きとキャプションに含めます。
- MuPDF WASM Worker が添付ファイルを直接読み、ページ数とテキストを抽出し、640 px の検出画像と PDF 座標からの高解像度 PNG を生成します。Reader サイドバーとメイン画面のバッチ処理は同じローカル結果を共有します。
- 最適化 Q8 モデルを XPI に内蔵し、インストール済みコピーを正確なサイズと SHA-256 で検証。その検証済みバイト列を Worker に渡し、推論前に SHA-256 を再検証。
- 添付ファイルごとの結果索引を JSON、抽出画像を PNG として Zotero データディレクトリに保存。
- 再解析時にページ単位でローカル結果を置換するか、不足分だけを追加。
- 解析がキャンセルされた場合やページ書き込みに失敗した場合、そのページで新規作成した注釈ミラーをロールバックします。未コミットの PNG 書き込みは削除し、上書き前の PNG を復元します。
- 解析をキャンセル可能。キャンセルでは対象の推論 Worker を終了し、後続処理のために再構築します。検出用描画は 640 px のままです。キャッシュにない各結果は PDF 矩形から直接描画され、長辺目標 2400 px、最大 6 倍・800 万画素に制限されるため、高解像度の全ページキャンバスは作りません。
- 抽出可能なテキストがないページもスキップせず検出対象にします。テキストがあるページでは、英語、中国語、イタリア語、ロシア語の完全な図表表記を使って候補をより厳密に絞り込みます。
- PDF リーダー左側の Zotero Figure アイコンを唯一のメイン入口として使用。リーダー上部のツールバーにはボタンを追加しない。
- 幅に追従するカードは PDF ページ順、同じページ内では上から下、左から右の表示位置順に並びます。**すべて**、**図**、**表**、**数式**のフィルターには該当する結果件数も表示されます。ローカル PNG は表示領域の近くで遅延読み込みされ、取り消し可能な Blob URL と最大 3 件の同時画像読み込みを使用します。
- 長いキャプションは既定で折りたたまれ、クリックで展開または再度折りたためます。
- サイドバーのアクションバーから解析、キャンセル、全結果のノート追加、更新、ローカル結果の消去を実行。消去するとサイドバーは直ちに空になり、JSON と PNG はバックグラウンドで削除されます。既存の Zotero 注釈ミラーは削除されません。
- Reader の解析進捗は、割合、プログレスバー、ローカライズされた現在の処理段階としてサイドバー内に直接表示され、別の進捗ウィンドウは開きません。
- Zotero PDF Translate がインストールされていれば、アクションバーでキャプションを翻訳し、もう一度押して原文に戻せます。成功した翻訳は対象言語ごとにローカルキャッシュされ、再利用されます。
- 既存のローカル結果は、アクションバーから必要なときに Zotero 注釈のミラーへ変換できます。
- 各カードのメニューから画像のコピー、保存、ピン留め、キャプション編集、ページ全体のドラッグ可能なプレビュー上での切り抜き補正、該当ページへの移動、ノートへの追加、削除が可能。補正後は高解像度 PNG を再描画し、再解析後も維持します。
- 必要に応じて、結果を `Figure N`、`Table N`、`Formula N` タグとキャプションコメント付きの Zotero 標準画像注釈として複製。既定では無効。
- 設定画面には内蔵モデルの保守と任意の注釈同期だけを残し、同期の説明はコンパクトな疑問符ヘルプアイコンから確認できます。
- 1 枚または全結果から、PNG を実体のある埋め込み添付ファイルとして含む Zotero ノートを作成。注釈ミラーがなくても、ノート画像をクリックすると元 PDF の対応する切り抜き位置へ移動できます。
- 英語、簡体字中国語、イタリア語、ロシア語の UI。

## 必要環境

- Zotero 9 のみ。
- [最新リリース](https://github.com/MuiseDestiny/zotero-figure/releases/latest)の XPI。

現在のローカル推論では Java と `pdffigures2.jar` は不要です。

## インストールと設定

1. 最新リリースから `zotero-figure.xpi` をダウンロードします。
2. Zotero の `ツール > プラグイン` でファイルからのインストールを選び、XPI を指定します。
3. PDF を開き、左サイドバーの Zotero Figure アイコンを選んで解析を開始します。内蔵モデルは自動的に準備・検証され、別途ダウンロードは不要です。

## 内蔵モデル

Zotero Figure は未使用出力を削除した Q8 `optimized-q8-6c25a56c` のみを内蔵します。サイズは 19,505,323 バイト、SHA-256 は `6c25a56caf796a074e26def15eea9018686836155fd9e15e5e0950e9c08a4cac` です。プラグインが使用する `output0` テンソルを完全に保持し、未使用の 7 出力分岐を削除しています。XPI から Zotero データディレクトリの `zotero-figure/models/` にコピーし、解析前に検証します。

XPI を入手した後は、モデルのために GitHub や Hugging Face へ接続する必要はありません。同一 XPI を GitHub Releases と地域ミラーで配布し、SHA-256 が一致することを確認してください。詳細は[配布ポリシー](MODEL_DISTRIBUTION.md)を参照してください。

## 使い方

1. Zotero リーダーで PDF 添付ファイルを開きます。
2. 左サイドバーの Zotero Figure アイコンを選択します。リーダー上部のツールバーに Zotero Figure ボタンはありません。
3. アクションバーの **図、表、数式を解析** を選び、ページ描画と検出の完了を待ちます。
4. **すべて**、**図**、**表**、**数式**を切り替えます。カードメニューから画像のコピー、保存、ピン留め、補正、キャプションの編集、該当ページへの移動、ノートへの追加、削除を実行できます。
5. Zotero PDF Translate がインストールされていれば、言語ボタンでキャプションを翻訳し、もう一度押して原文に戻します。
6. 必要に応じて **全結果をノートに追加**、**更新**、**ローカル結果を消去**を使用します。消去対象はプラグインのローカル JSON と PNG のみで、既存の Zotero 注釈ミラーには影響しません。
7. 同期される画像注釈も作成する場合は、プラグイン設定で **解析後に結果を Zotero 注釈へ同期**を有効にします。既定では無効です。
8. バッチ処理では、ライブラリの文献アイテムまたは PDF 添付ファイルを複数選択して右クリックし、**PDF Figure > 図、表、数式を解析**、**図、表、数式を解析してノートへ追加**、または **図、表、数式を解析して注釈を作成**を選びます。PDF は順番に処理され、Reader タブを開く必要はありません。

サイドバーは常にプラグイン独自のローカル結果ストアを読み込みます。PDF 添付ファイルごとのメタデータは Zotero データディレクトリ内の `zotero-figure/results/<libraryID>/<attachmentKey>/manifest.json` に、PNG は隣接する `images/` ディレクトリに保存されます。schema v5 の manifest は、手動キャプションと切り抜き補正、対象言語別の翻訳、バージョン付き画像キャッシュ識別情報を保存します。検出された値はキャッシュ照合用に別途保持されるため、手動キャプションと切り抜き補正は再解析後も維持され、キャプションの編集時にはその結果の古い翻訳キャッシュが消去されます。添付元フィンガープリント（ファイルサイズと更新日時。取得できない場合は Zotero アイテムのバージョンにフォールバック）、解析バージョン、モデルハッシュ、プレビューバージョン、結果フィンガープリント、現在の切り抜きフィンガープリントが同じで PNG ファイルも存在する場合に限り、再解析ではその PNG を再利用します。manifest、翻訳キャッシュ、PNG は Zotero Sync の対象ではありません。注釈同期を有効にすると、同期や他プラグインとの互換性のために標準注釈のコピーが追加作成されますが、サイドバーのデータソースは変わりません。ノート内の画像は埋め込み添付ファイルであり、ローカル PNG パスへのリンクではありません。注釈ミラーを無効にしていても、ノート画像をクリックすると元 PDF の対応する切り抜き位置へ移動できます。

MuPDF、モデル、Worker の準備はリーダーのアイドル時に開始されます。準備完了前に解析を始めた場合、初回は時間がかかることがあります。処理時間は PDF、CPU、利用可能メモリによって変わります。

解析中に同時にスケジュールされるページは最大 3 件です。各ステージは個別に制限され、検出は最大 2 ページ、MuPDF 描画要求は 1 件、高解像度領域処理は 1 件、保存処理は 1 件です。検出画像の長辺は 640 px です。キャッシュにない結果は PDF 矩形から 1 件ずつ直接描画し、長辺目標 2400 px、最大 6 倍・800 万画素に制限します。2 個の常駐 ONNX Worker がそれぞれ 1 推論スレッドで並行動作し、キャンセル時は対象 Worker を終了します。Q8 セッションは複製されますが、従来の高解像度全ページキャンバスは不要です。詳細は[性能予算](PERFORMANCE.md)を参照してください。

## プライバシー

PDF の解析と描画は内蔵 MuPDF WASM、検出は Zotero 内の Transformers.js と ONNX Runtime Web で実行されます。PDF ページを外部サービスへ送信せず、実行時にモデルをダウンロードしません。

ローカルの結果 JSON と PNG は Zotero データディレクトリに残ります。ユーザーがそのディレクトリを別途バックアップまたは同期するか、注釈同期を有効にして追加コピーを作成しない限り、端末外へ送られません。

## 開発

Node.js 20.10 以降が必要です。

```bash
npm install
npm run check
npm run build
```

`npm run check` はフォーマット、ESLint、TypeScript、テスト、バンドルを検証します。`npm run build` は `build/zotero-figure.xpi` を生成します。`npm start` の前に `scripts/zotero-cmd-default.json` を `scripts/zotero-cmd.json` へコピーし、ローカルの Zotero パスを設定してください。

## アーキテクチャ

| パス                  | 責務                                          |
| --------------------- | --------------------------------------------- |
| `src/domain`          | Zotero に依存しないレイアウト型と照合ロジック |
| `src/features`        | リーダー UI、ライブラリのバッチ操作、設定     |
| `src/services`        | 解析、推論キュー、画像切り出し、ローカル保存  |
| `src/platform/zotero` | Zotero API との型付き境界                     |
| `addon`               | Bootstrap、翻訳、Worker、モデル情報           |
| `scripts`, `tests`    | 再現可能なビルドと自動検証                    |

ドメインロジックは Zotero のグローバル変数に依存させず、非公開 API へのアクセスはプラットフォームアダプターへ隔離します。

## 現在の制限

優先順位付き一覧は [docs/KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md) にあります。主な残課題はスキャン PDF からのキャプション抽出、Zotero リーダーの非公開 API リスク、実際の Zotero 9 環境でのエンドツーエンドテストです。
