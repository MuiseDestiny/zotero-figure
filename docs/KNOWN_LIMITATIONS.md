# Zotero Figure 现存不足与下一步修复清单

本清单以当前代码和已经执行的验证为准。内置并裁剪未使用输出的 Q8 模型及双重完整性校验、独立于 Reader 的 MuPDF WASM 附件解析、图/表/独立公式检测、表格脚注合并、640 像素检测图、按 PDF 坐标直接渲染高清局部、可持久化的手工区域校正、两个单线程 ONNX Worker、分阶段有界并发、带版本身份缓存的本地 JSON + PNG 结果仓库、视口附近图片懒加载、专用左侧栏、主界面逐篇批处理、可选标注镜像和嵌入图片笔记已经实现。

## P0：正确性与兼容性

1. **缺少真实 Zotero 9 端到端测试。** 当前已有格式、lint、类型、领域逻辑、模型内嵌、本地化和构建检查，也在 Zotero 10 beta 中做过运行时调试，但尚未在真实 Zotero 9 上完整验证安装、设置页、首次模型释放、侧栏注册与重新挂载、图/表/公式分析和取消、表格脚注、区域校正、本地结果持久化、可选标注同步、笔记创建、清空结果以及卸载流程。
2. **侧栏仍依赖 Zotero 阅读器私有 API 和 DOM 结构。** PDF 页数、文字和图片渲染已改由 MuPDF WASM 从附件文件完成，不再依赖 `_pdfRenderer`；但 Zotero 没有公开的自定义阅读器左侧栏注册接口，插件仍需读取 Reader 内部字段并注入 DOM。Zotero 9 的小版本升级可能导致入口、重新挂载、页面跳转或图片操作失效，但不会阻止后续主界面从附件路径执行批处理。
3. **JSON、PNG 与标注镜像不是一个原子事务。** 清单文件通过临时文件原子替换，但 PNG 必须先写入；取消或清单提交失败时，插件会删除新 PNG 并还原被覆盖的 PNG。如果进程在清理期间终止，或回滚本身遇到 I/O 失败，仍可能留下未被清单引用的图片。开启标注同步时，本地结果会先提交，再更新 Zotero 标注，因此标注阶段失败时两份数据也可能暂时不一致。
4. **关闭标注同步不会自动清理旧镜像。** 用户曾开启同步、随后关闭并重新分析时，侧栏会使用最新本地结果，但以前创建的 Zotero 标注可能继续存在。清空本地结果不会删除这些镜像；当前只能逐张删除对应结果或手动处理标注。后续需要明确的“修复/移除标注镜像”操作和状态提示。
5. **本地结果不使用 Zotero Sync。** `manifest.json` 和 PNG 只存在于当前 Zotero 数据目录；换电脑、重建数据目录或只依赖 Zotero 同步时，侧栏结果不会自动迁移。开启标注同步只能提供另一种可同步副本，不能恢复本地清单，也没有结果导入、导出或重建功能。

## P1：识别质量与性能

6. **扫描页的说明提取仍不完整。** 没有可提取文字的页面现在会直接进入检测，不再因文字为空而被跳过；但检测只能定位视觉区域，缺少文字层时仍可能无法恢复图注、公式编号和表格脚注文字。包含文字的页面使用多语言图表公式提示词及常见数学符号进行预筛选，其他语言或没有明显提示的页面仍可能被跳过。
7. **主体、说明和脚注匹配仍是启发式。** 当前依据水平/垂直重叠、方向和距离匹配图注、表注、公式编号与表格脚注，主要提取阿拉伯数字编号；跨栏图注、多面板图、连续表格、罗马数字和字母编号可能匹配错误。用户可以在卡片菜单中校正最终裁图区域，但不能在校正器中重新绑定说明或脚注。
8. **高清结果仍受 PDF 源质量和局部渲染上限约束。** MuPDF 会按每个检测框直接渲染 PNG，最长边目标为 2400 像素、比例不超过 6 倍、单图不超过 800 万像素，不再创建整页高清画布。极小图表可能达到 6 倍上限，极端长宽比区域可能先达到像素上限；扫描 PDF 的源图本身模糊时也无法恢复细节。
9. **解析流水线采用有界双 Worker 并发。** 同时最多调度 3 页，其中检测阶段最多 2 页；MuPDF 渲染、高清局部阶段和存储各自最多 1 项操作。两个持久 ONNX Worker 各使用一个推理线程，能并发检测两页，但也会复制 Q8 模型会话并提高常驻内存。取消正在执行的推理会终止受影响的 Worker，后续任务再重建。PNG 缓存只有在附件源指纹、分析版本、模型哈希、预览版本、检测结果指纹、当前裁图指纹和文件存在状态全部匹配时才复用。详细内存预算见 `docs/PERFORMANCE.md`。
10. **侧栏尚未虚拟化全部卡片。** 图片只在接近视口时通过可撤销的 Blob URL 懒加载，并限制为最多 3 个并发文件读取，离开视图或重新渲染时会释放 URL，不再一次生成全部 PNG Data URI。但当前筛选下的卡片元数据和 DOM 仍会整体创建；结果数量非常多时，DOM 规模以及滚动过程中的图片解码仍可能造成开销。
11. **首次准备和双模型会话会占用额外内存。** 安装到数据目录的 19,505,323 字节 Q8 模型先按大小和 SHA-256 校验，随后分别传给两个推理 Worker，再次校验后创建两个会话。MuPDF 还需要 WASM 线性内存、PDF 字节副本和页面 DisplayList。此流程完全离线，但首次准备、批量打开大 PDF 或取消后重建 Worker 时会产生额外内存、哈希计算和磁盘读取开销。
12. **阈值不可配置。** 分类置信度、NMS、图注/公式编号/表格脚注最大距离和页面预筛选规则目前写在代码中，用户无法针对不同论文版式调整。
13. **Q8 是唯一运行模型。** 这保证所有用户使用同一份速度、体积和质量经过验证的模型，但无法在设置中切换模型来诊断特定文档的精度问题；模型升级必须随插件版本发布。
14. **部分页面失败的信息不够完整。** 完成日志已经输出 MuPDF、检测、推理、局部渲染、PNG 编码和存储等阶段耗时，但界面完成提示仍只汇总结果数量，没有列出失败页、预筛选跳过页或每页错误。

## P2：数据生命周期、交互与发布

15. **缺少自动的本地存储清理。** 删除 PDF 附件、删除资料库、卸载插件或附件 key 变化时，`zotero-figure/results/` 下的目录不会自动回收；设置页也没有占用空间统计、全局清理或备份入口。
16. **笔记是结果快照。** 添加到笔记会创建新的 Zotero 笔记和嵌入式 PNG；后续重新分析、删除本地结果、修改说明或校正裁图不会更新已有笔记，重复执行也可能产生重复笔记和图片附件。
17. **运行时界面只有四种语言。** 当前提供英语、简体中文、意大利语和俄语；README 还提供日语和西班牙语，但插件 UI 尚未覆盖这两种语言。
18. **XPI 体积和更新流量较大。** 每次代码更新都会重新分发约 20 MB 的模型，即使模型本身没有变化。后续可评估差分更新或双镜像发布，但不能牺牲离线可用性、模型一致性和完整性校验。
19. **发布与兼容验证尚未接入 CI。** 本地质量门禁覆盖模型哈希和 XPI 构建，但还需要 Zotero 9 安装冒烟测试、侧栏交互测试、国内外 XPI 镜像哈希校验和正式发布流程。
20. **缺少用户可导出的诊断信息。** 设置页能显示模型状态、大小和短哈希，但尚未汇总 Zotero 版本、运行时、线程、本地结果路径、失败页、标注镜像状态和安全脱敏后的日志。
21. **翻译功能依赖 Zotero PDF Translate。** 未安装该插件时不会显示翻译按钮；成功译文会按目标语言持久保存并复用，翻译服务失败时保留原文。可用语言、延迟、翻译质量和 API 兼容性仍取决于 Zotero PDF Translate 及其配置的服务。
22. **批处理控制仍较基础。** 主界面会按选择顺序逐个处理 PDF，普通文献只解析 Zotero 选出的最佳 PDF 附件；当前没有队列预览、整批取消、暂停/恢复或“同一文献解析全部 PDF 附件”。单篇失败会写日志并继续后续条目，但完成浮窗不会展开每篇失败原因。

## 建议的下一步

1. 在真实 Zotero 9 上验证 MuPDF ESM/WASM 资源加载、首次双模型会话、旋转/CropBox 页面、侧栏完整生命周期、分析和取消、本地持久化、标注开关、笔记创建与卸载。
2. 为本地仓库增加事务恢复、孤立 PNG 清理、附件删除监听、空间统计以及结果导入导出。
3. 增加标注镜像状态检测和显式的修复/移除操作，覆盖“开启后又关闭同步”的生命周期。
4. 用稀疏/密集 100 页 PDF 和主界面批处理实测双 ONNX Worker 的吞吐、峰值内存与温度；必要时根据设备内存提供自动降级为单 Worker 的策略。
5. 为主界面批处理增加队列预览、取消/暂停、失败详情和“最佳 PDF / 全部 PDF”选择，并为笔记写入增加重复检测。
6. 为扫描版 PDF 增加 OCR 或其他图注恢复路径，扩展更多语言的完整提示词，并改进复杂排版的候选策略、失败页和跳过页报告。
7. 将完整质量门禁接入 CI，建立 GitHub 与国内镜像发布流程，并自动核对 XPI SHA-256。
