# Zotero Figure 现存不足与下一步修复清单

本清单以当前代码和已经执行的验证为准。内置 Q8 模型及双重完整性校验、可取消分析、640 像素检测页、每个结果页一次受限高清渲染后复用裁图、分阶段有界并发、持久单 Worker、带版本身份缓存的本地 JSON + PNG 结果仓库、视口附近图片懒加载、专用左侧栏、可选标注镜像和嵌入图片笔记已经实现。

## P0：正确性与兼容性

1. **缺少真实 Zotero 9 端到端测试。** 当前已有格式、lint、类型、领域逻辑、模型内嵌、本地化和构建检查，也在 Zotero 10 beta 中做过运行时调试，但尚未在真实 Zotero 9 上完整验证安装、设置页、首次模型释放、侧栏注册与重新挂载、分析和取消、本地结果持久化、可选标注同步、笔记创建、清空结果以及卸载流程。
2. **依赖 Zotero 阅读器私有 API 和 DOM 结构。** Zotero 没有公开的自定义阅读器左侧栏注册接口，插件需要读取 `_internalReader`、`_pdfRenderer` 等私有字段，并把标签和面板注入阅读器 DOM。Zotero 9 的小版本升级可能改变字段、DOM 层级或 React 生命周期，导致入口、重新挂载、页面跳转或图片操作失效。
3. **JSON、PNG 与标注镜像不是一个原子事务。** 清单文件会通过临时文件替换，但 PNG 必须先写入；取消、磁盘写入失败或进程退出可能留下未被清单引用的图片。开启标注同步时，本地结果会先提交，再更新 Zotero 标注，因此标注阶段失败时两份数据也可能暂时不一致。
4. **关闭标注同步不会自动清理旧镜像。** 用户曾开启同步、随后关闭并重新分析时，侧栏会使用最新本地结果，但以前创建的 Zotero 标注可能继续存在。清空本地结果不会删除这些镜像；当前只能逐张删除对应结果或手动处理标注。后续需要明确的“修复/移除标注镜像”操作和状态提示。
5. **本地结果不使用 Zotero Sync。** `manifest.json` 和 PNG 只存在于当前 Zotero 数据目录；换电脑、重建数据目录或只依赖 Zotero 同步时，侧栏结果不会自动迁移。开启标注同步只能提供另一种可同步副本，不能恢复本地清单，也没有结果导入、导出或重建功能。

## P1：识别质量与性能

6. **扫描页的图注提取仍不完整。** 没有可提取文字的页面现在会直接进入检测，不再因文字为空而被跳过；但检测只能定位视觉区域，缺少文字层时仍可能无法恢复图注内容和编号。包含文字的页面使用英语、中文、意大利语和俄语的完整图表提示词进行预筛选，其他语言或没有明确图表提示词的页面仍可能被跳过。
7. **图表与图注匹配仍是启发式。** 当前依据水平重叠、上下方向和距离匹配，主要提取阿拉伯数字编号；跨栏图注、多面板图、连续表格、罗马数字和字母编号可能匹配错误。
8. **高清结果仍受 PDF 源质量和渲染上限约束。** 每个含结果的 PDF 页面只高清渲染一次，比例不超过 4 倍、总像素不超过 1200 万、单边不超过 8192 像素；同页的多个检测框都从这张页面图像裁出，侧栏、嵌入笔记、复制与另存使用这些本地 PNG。边界能控制峰值内存，但超大页面或极小图表可能无法获得完整 4 倍分辨率；扫描 PDF 的源图本身模糊时也无法恢复细节。
9. **解析流水线采用保守的分阶段并发。** 同时最多调度 3 页，其中检测阶段最多 2 页；检测页渲染、高分辨率结果页渲染和存储各自最多 1 页或 1 项操作。这样可以让文本提取、检测与存储重叠，同时保证任一时刻最多保留一个高清页面画布。模型仍由单个持久 Worker 执行，最多使用 4 个 WASM 线程并为 Zotero 预留逻辑容量；取消正在执行的推理会终止 Worker，后续任务再重建，避免后台继续占用 CPU。PNG 缓存只有在附件源指纹（文件大小和修改时间，无法取得时回退为 Zotero 条目版本）、分析版本、模型哈希、预览版本、结果指纹和文件存在状态全部匹配时才复用，因此源 PDF、模型、算法或裁图策略变更都会重新生成。
10. **侧栏尚未虚拟化全部卡片。** 图片只在接近视口时通过可撤销的 Blob URL 懒加载，并限制为最多 3 个并发文件读取，离开视图或重新渲染时会释放 URL，不再一次生成全部 PNG Data URI。但当前筛选下的卡片元数据和 DOM 仍会整体创建；结果数量非常多时，DOM 规模以及滚动过程中的图片解码仍可能造成开销。
11. **模型准备仍会短时占用额外内存。** 安装到数据目录的约 20 MB Q8 模型先按大小和 SHA-256 校验，其完整字节随后传给推理 Worker，并在 Worker 内再次计算 SHA-256 后才创建会话。此流程不访问网络且能防止校验后替换，但首次准备或取消后重建 Worker 时会产生额外的短时内存、哈希计算和磁盘读取开销。
12. **阈值不可配置。** 分类置信度、NMS、最大图注距离和页面预筛选规则目前写在代码中，用户无法针对不同论文版式调整。
13. **Q8 是唯一运行模型。** 这保证所有用户使用同一份速度、体积和质量经过验证的模型，但无法在设置中切换模型来诊断特定文档的精度问题；模型升级必须随插件版本发布。
14. **部分页面失败的信息不够完整。** 失败页会写入日志，但完成提示只汇总本地结果和可选标注的创建、删除、跳过数量，没有列出失败页、预筛选跳过页或各阶段耗时。

## P2：数据生命周期、交互与发布

15. **缺少自动的本地存储清理。** 删除 PDF 附件、删除资料库、卸载插件或附件 key 变化时，`zotero-figure/results/` 下的目录不会自动回收；设置页也没有占用空间统计、全局清理或备份入口。
16. **笔记是结果快照。** 添加到笔记会创建新的 Zotero 笔记和嵌入式 PNG；后续重新分析、删除本地结果或修改图注不会更新已有笔记，重复执行也可能产生重复笔记和图片附件。
17. **运行时界面只有四种语言。** 当前提供英语、简体中文、意大利语和俄语；README 还提供日语和西班牙语，但插件 UI 尚未覆盖这两种语言。
18. **XPI 体积和更新流量较大。** 每次代码更新都会重新分发约 20 MB 的模型，即使模型本身没有变化。后续可评估差分更新或双镜像发布，但不能牺牲离线可用性、模型一致性和完整性校验。
19. **发布与兼容验证尚未接入 CI。** 本地质量门禁覆盖模型哈希和 XPI 构建，但还需要 Zotero 9 安装冒烟测试、侧栏交互测试、国内外 XPI 镜像哈希校验和正式发布流程。
20. **缺少用户可导出的诊断信息。** 设置页能显示模型状态、大小和短哈希，但尚未汇总 Zotero 版本、运行时、线程、本地结果路径、失败页、标注镜像状态和安全脱敏后的日志。
21. **翻译功能依赖 Zotero PDF Translate。** 未安装该插件时不会显示翻译按钮；成功译文会按目标语言持久保存并复用，翻译服务失败时保留原文。可用语言、延迟、翻译质量和 API 兼容性仍取决于 Zotero PDF Translate 及其配置的服务。

## 建议的下一步

1. 在真实 Zotero 9 上验证安装、首次模型释放、侧栏完整生命周期、分析和取消、本地持久化、标注开关、笔记创建与卸载。
2. 为本地仓库增加事务恢复、孤立 PNG 清理、附件删除监听、空间统计以及结果导入导出。
3. 增加标注镜像状态检测和显式的修复/移除操作，覆盖“开启后又关闭同步”的生命周期。
4. 如果超大结果集仍产生明显 DOM 开销，为完整卡片列表增加虚拟化；继续保留当前视口附近 PNG 懒加载和有界文件读取。
5. 为扫描版 PDF 增加 OCR 或其他图注恢复路径，扩展更多语言的完整提示词，并改进复杂排版的候选策略、失败页和跳过页报告。
6. 将完整质量门禁接入 CI，建立 GitHub 与国内镜像发布流程，并自动核对 XPI SHA-256。
